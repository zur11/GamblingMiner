  - **P16.7 — two dividend defects + the no-quorum default (2026-07-31/08-02):** (a) `TryConvertCompanyReserves`' 5% deficit gate shared the `totalValueSc` denominator with the quantity it bounded, making 5% a **hard floor on the voted reserve target** — any company below it was pinned at 0 SC forever (Slush Pool at 1.87%); now measured against `targetSc`. (c) `payoutResult` initialised to `0m` meant a unanimous abstention paid **no dividend at all** for a quarter — now the **category default**, with `;no_quorum` on the trace row. *A resolver's "nobody answered" value is a design decision, not an initializer.*
  - **P16.8 — the player can abstain (D-16.19, subphases b–k):** `PlayerAutoAbstain` (standing, outranks the pause) + `TryRegisterPlayerAbstention` (manual, via an Abstain **toggle** resolved by the single `Submit Ballot` axis). - Company **pending-work tint** — red / green / mocha / black (Step 14 ND.10h, 2026-07-23): the second colour axis on a founded company's BlockExplorer row — where the border says "what do I own here?", the row label + button say **"what must I do here?"**. Board vote pending → **red** `Vote →` (the game-pausing case, unchanged from ND.8b.3); dividends claimable → **green** `Claim →`; both → **mocha** `#C08552` `Vote →`; neither → untinted `Details →` with a **black border**. A pure function of current state (voting clears the flag, claiming clears the claimable) — no history, no persisted state, no event. Two rules: **mocha is hand-picked, never an RGB average** (additive mixing gives a yellow-green `#A6C364`; the pigment/subtractive mix in CMY gives `#4D2600`, whose hue is kept and value lifted for legibility on dark) — and **"claimable" means PAYABLE, not non-zero**: `NetworkRoot.HasPlayerClaimableDividends` tests `(Sc > 0 && ScReserve > 0) || Btc > medianFee`, since `TryClaimPlayerCompanyDividends` deducts the fee from the claim itself and pays SC only up to the company reserve — the naive `> 0` test yields a permanently-green button that pays nothing. It is the SINGLE source for both the row button and `CompanyDetails`' "Claimable now:" line (which appends "— below the network fee; still accruing"), the ND.10d "a displayed signal must share its source with the action it advertises" rule. Note `ApplyButtonBorder` overrides all four Button stylebox states (`normal`/`hover`/`pressed`/`focus`) — overriding only `normal` makes the border vanish on hover. The wiring is one funnel, `NetworkRoot.AttachDerivedWalletIfSeeded`, and its test is **always `record.HasSeed`, never the node's kind** (D-16.6/17) — which is what leaves the deferred **ghost typology** (`PRIVATE_ROADMAP.md`) implementable without reopening the decision. **Two traps worth remembering: (1)** `bot_wallet_registry.json` is an **identity** file, exempt from the world-reset delete list, so a `WorldFormatVersion` bump does NOT renew it — it carries its own `RegistryFormatVersion` (bump both together, and the registry's is the one that actually regenerates the seeds); **(2)** the removal check for the explorer cosmetics found that the long-standing scope list was **incomplete** — **passphrase wallets** spend and had no `ReceiveWallet`, making them the last single-address change-producer. They are migrated too (and, being created mid-session, need a single-node rescan at registration or their change-held funds go unowned). Both explorer cosmetics (`IsSelfChangeTransaction` / `ExternalOutputs`) are **deleted**; §29.9 is now history. **General rule the removal taught: when deleting a workaround, re-derive the set of cases it covered from the CODE — never trust the scope list written when it was added.**

  **⚠ P16.2's fallout, found the next day at P16.6 (2026-07-31) — three defects, all shipped fixed; full write-ups `Documentation/ProjectDesignManual.md` §30.10, §22.20, §40.7.** Giving ~74 more participants a seed retired premises that eleven call sites silently depended on:
  1. **Bots could spend change they could not see.** The spend path (`BuildAndBroadcastUtxoSpend`) unions the owned address set, but every affordability read used `GetAddressSpendableBalance(node.WalletAddress)` — base only. Each bid therefore moved ~50 BTC out of view, and three bids drove bot_1's apparent balance 300 → 150, tripping the ND.10e reserve guard while it held 299.9. Eight engine reads moved to `AggregateSpendable`; identity matching (`BuildBotPoolOpportunities`, the escalation helpers, `BuildAuctionBidderIdentity`'s **bot** half, `ReBidProbabilityLabelForSlot`'s self-eviction guard, `AccumulateCompanyInflows`) moved to the owned set via the new `OwnedAddressSet(node)`; and `BotsBtcWallets` + its two P16.3 subclasses, which were showing **`0.00000000 BTC` for bots holding ~300**, moved to the new `GetNodeWalletTotals(nodeId)`. **Rule: when a capability is extended to a new class of participant, the reads that were correct only because that class lacked it will not announce themselves — they compile, run, and return a plausible number. Grep for the retired PREMISE, not just the code implementing it.**
  2. **The six-minute launch.** `Secp256k1.ScalarMul` was affine, so every point op needed a modular inverse via a full 256-bit `ModPow` — **~384 modexps and 127 ms per address derivation**. Survivable at ~6 seeded wallets; at ~79 the launch rescan's ~1,900 derivations became ~4 minutes. Now Jacobian (one inversion per scalar multiply): **127 ms → 3.3 ms, 31×**, bit-for-bit identical over 490 vectors + the `k=1` known-answer test ⇒ **no `WorldFormatVersion` bump**. The stale cost note that hid it ("~20 SHA256 per node") was corrected in place — see Pattern 6's closing rule.
  3. **A bot bid for ten blocks against its own reserve guard** — see the reserve-guard entry in the Referral auction row of Canonical Decisions.
